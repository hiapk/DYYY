# 仅看一次重复查看：真机验收

目标环境为 RootHide / iOS 16.5 / 抖音 39.8.0（build 398016）。当前仅完成静态调用路径核对、策略单测与构建检查；是否能再次获取、解密和展示资源，需要按此表真机验证。

当前版本为 2.3-8。使用自己的测试账号互发新的仅看一次文字、图片和视频。在 DYYY「隐私」开启「仅看一次重复查看（实验）」，默认关闭。验收范围为同一进程内重复查看，不承诺重启后仍可用；不要用旧版已经消费、消失的消息判断新版本是否通过。

| 场景 | 预期及检查点 |
| --- | --- |
| 默认关闭 | 原生仅看一次行为不变；现有私信已读、输入状态、广告章节等开关不受影响。 |
| 接收文字反复重进 | 新发一条文字，连续进出聊天至少五次，每次等待超过原生查看时长；重点检查第三、四次仍显示文字，不变成撤回提示或直接消失。 |
| 接收图片 | 打开、等待查看结束、返回会话，再次打开；能实际显示图片，不能只验证气泡文案。 |
| 接收视频完整播放 | 播完返回，再次打开并完整播放，检查画面和声音。 |
| 接收视频提前返回 | 播放中返回，再次打开；没有黑屏、加载卡住或播放器残留声音。 |
| 离开会话与后台切换 | 返回消息列表再进入会话、切后台再回来，分别重复打开；记录是否仍可用。 |
| 播放器清理 | 退出图片页后无定时器持续弹窗；退出视频页后停止声音，普通视频播放正常。 |
| 原生失效 | 已过期、撤回、服务端或其他设备已标不可用的消息保持原生行为；不会强行显示为有效。 |
| 消息范围 | 普通文字/图片/视频、自己发送的消息保持原生行为。 |
| 关闭开关 | 后续查看与退出恢复原生消费处理；不要求关闭瞬间补报之前拦截的记录。 |
| 混合批次与弱网 | 普通/发送方消息仍上报；部分被拦时聚合回调失败，观察是否出现持续重试、刷日志或气泡状态异常。 |
| 重启进程 | 记录实际结果；首版不以跨重启可用作为通过条件。 |
| 缺失私有接口 | 整组 Hook 停用；开启开关时应提示当前版本缺少必要接口，其他功能可正常使用。 |

## 排查依据

- `DYYYWatchOnceKeep.xm`：消费 setter、缓存标记 setter、DataManager 上报，以及两个查看页的资源回填入口。
- 文字还通过 `readState` 的 2/4 位标志及独立 `TextWatchEnd` 记录控制消费；保留查询 `read_status` 和原始同步 `s:once_view_done` 的真实不可用处理，不全局拦截撤回或删除。
- `Sources/Features/DYYYWatchOnceKeepPolicy.m`：消息范围、空详情判定、混合批次与只完成一次的异步失败回调。
- 查看页退出会用空详情调用 `p_fillMessage:withContent:`；只跳过有效接收消息的资源字段清空，正常详情回填、播放器退出和观察者清理仍执行。没有额外保存资源文件或密钥。
- 原生 `watchEnd` getter 可能因时间、业务不可用状态直接写内部标记；该 getter 保持原样，测试通过不能说明可恢复已失效内容。
- 专用消费上报回调接收状态码对象和错误对象；混合批次的普通消息会发送，但聚合调用方仍收到失败，是否会重试需观察。
- 若无法再次打开，先区分气泡状态、资源字段、详情请求和实际解码失败；不要仅通过继续强制 BOOL 为 NO 掩盖原因。

策略测试：`sh tests/run-watch-once-keep-tests.sh`。测试不连接抖音服务端，不证明真机 Hook 命中或媒体资源可用。

文字 Hook 回归：`THEOS=/path/to/theos sh tests/run-watch-once-text-hook-tests.sh`。编译实际 Logos 源码，在模拟宿主中连续重建五次消息对象，另验真实失效、主动撤回、发送方与开关关闭；模拟结果不能代替上述端上验收。
